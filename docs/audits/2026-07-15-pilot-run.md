## Bugs the pilot caught (all fixed in VECTOR, on `v2-enforcement`)

1. **`new-project.md` `.gitignore` inline-comment bug** — git has no trailing comments, so
   `mock/  # ...` and `.vector/state.json  # ...` matched nothing; the disposable mock and
   runtime state would leak into git in **every** project. Fixed (comments on their own line;
   added `playground/`).
2. **`bootstrap-github.md` branch-protection command broken** — used `-f` string fields where
   the API needs typed booleans/integers/null → **422 (`"true" is not a boolean`)**. Exactly
   the finicky failure flagged in the confidence assessment. Fixed to a typed JSON body via
   `--input`, plus a documented note that the API returns **403 on a private free-plan repo**
   (needs Pro or a public repo).

## Learnings noted for Phase B (not bugs — carry forward)

- **`vector-revert` must handle merge commits** (`git revert -m 1`) — ship-issue tags the merge
  commit, and reverting it needs the mainline parent flag.
- **A revert that removes tests trips `test-protection`** — `vector-revert` should carry a
  `TEST-CHANGE-JUSTIFICATION` block when it touches tests; and you don't revert the *foundation*
  (reverting T001 correctly failed ci-tests + test-protection).
- **The coverage baseline needs ratcheting up** after the first real coverage; at `0.0` the
  ratchet has no teeth yet (test-protection was the net that actually caught the weakening here).

## Limitations (real deviations — do NOT treat as fixed)

- **Single GitHub identity** (`fedeglan`) — no dedicated machine user (I cannot create GitHub
  accounts). The "machine ≠ human" property that makes branch protection meaningful in
  production was **not** exercised.
- **Repo made public** to enable branch protection on the free plan. A production repo would be
  private on Pro/Team.
- **Only T001 of 5 issues was built** through the full gated loop. T002–T005 follow the
  identical, proven loop; they were not executed (no manufactured green).
- **`webapp` visual gates** (views/mock/baselines/Explorer) remain paper-only.
- **The Tier-2 runner and Act III** are unbuilt (Phase B/E/F) — unchanged, and documented as such.

## Addendum — the app was finished (T002–T005 + phase close), 2026-07-15

The whole `linksaver` MVP was subsequently built through the gated L1 loop, with the Federico
subagent reviewing every PR (adversarial token attacks on the auth boundary, mutation-testing
the cascade, driving all boundary cases over HTTP himself). Result: 5 issues shipped, all 6
stories covered, the owner/viewer boundary proven at the network layer, 33 unit tests.

**The Explorer earned its place in the method.** schemathesis (the service-api Explorer) ran at
phase close and found **3 server-error (500) bugs the 32 unit tests missed** — int64 overflow on
huge ids and pagination values. Fixed via two gated `/fix-bugs` PRs, each with a regression test;
re-run: **626 cases pass, 0 server errors**. This is the exact division of labor the method claims:
unit tests + CI verify conformance-to-spec; the Explorer catches emergent behavior they can't.

**The escalate → `/change-scope` loop was exercised end-to-end.** The remaining 8 schemathesis
findings were spec-conflicts (the frozen `api-spec.yaml` under-described its own error contract —
undocumented 422s, an `Error{detail:string}` schema that was *lying* about the array-shaped 422
body, an over-loose `url`). Per the fix policy the builder **escalated** rather than resolving;
Federico ruled ACCEPT-the-phase-but-resolve-before-release and directed a `/change-scope`. It was
applied through the sanctioned marker window (`.vector/change-scope-open`), reconciling the spec
(findings 8 → 5; the tail is schema-strictness edges + a mixed 422 body, tracked). Federico's own
closing note: the Explorer finding 8 contract defects in his freeze means his Act-I review
**under-scrutinized the error-response contract** — a finding about the *design gate*, logged for
DECISIONS.md (the freeze checklist should assert error schemas + status-code completeness, not just
the happy path).

### Bugs the build/Explorer caught (all real)
- **P1 ×2 (code):** int64 overflow → 500 on id and on offset/limit. Fixed + regression tests, gated.
- **Decomposition error:** the DAG had auth ∥ repository, but the layering rule forbids SQL in auth,
  so auth depends on repository — caught by the method's own rule; reordered.
- **CI layering-check false positive:** a grep for SQL keywords tripped on the word `DELETE` in a
  router docstring. It should grep for `.execute(`/`sqlite3.connect` (execution calls). *And* it
  could not be fixed in the feature PR because `.github/workflows/` is CODEOWNERS-protected — the
  gate correctly refused single-identity self-approval. (Follow-up: a code-owner-approved PR.)

### Two corrections I owe, stated plainly (honesty over a clean story)
- **Branch protection was DROPPED when I toggled the repo private→public** (free-plan behavior) and
  I did not re-apply it. So the **T002–T005 app-build merges ran without active protection
  enforcement** — they were gated by CI-green + Federico's review (L1 human discipline), *not*
  mechanically. Phase A's enforcement proof (red PR blocked, admin refused) was real (protection
  active then), and I re-verified afterward that CODEOWNERS **does** block a frozen-path change
  under single-identity (`mergeState=BLOCKED`). **Finding for VECTOR:** any visibility change silently
  drops protection; `/bootstrap-github` and ops must re-verify/re-apply protection after one, and
  the audit's "CODEOWNERS backstops frozen paths" claim holds *only while protection is applied*.
- The change-scope's frozen-spec PR, under single-identity, needs the human's own admin-merge (a
  second reviewer in production) — the same correct CODEOWNERS wall as the layering-check fix.
